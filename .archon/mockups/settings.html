Archon Settings — information-architecture mockups

Seven mockups for the IA in .archon/settings-ia-proposal.md. Linear's settings page is the reference: a left settings rail, a narrow content column, sections of hairline-separated rows rather than a stack of cards, and a save bar that only exists when something is dirty. Every colour, radius and type size below is read from packages/web/src/theme/tokens.css — so this is a preview of the theme you have, not a picture of a different one. Switch theme and mode above; the mockups are live.

1 · The whole page

primary layout

Left rail groups by whose decision it is, which is the axis the engine already enforces. The content column is 700px — Linear's restraint; a settings row is unreadable at 1100px. Note what is absent: no Streaming, no Concurrency, no Paths rows. Those six keys have no consumer, so under the invariant they get no control.

2 · The scope chip, opened

the one new idea

This is the whole design in one control. The chip states where the value in force came from; clicking it shows the precedence stack with the winner highlighted and every band you could set instead. That is what "express per-project override rather than flatten it" looks like as a pixel — and the stack is rendered from buildAiProfile's real layering, so it cannot drift from what the engine does.

Five states. Colour is not decoration — it separates "someone chose this" from "nobody has".

An environment variable is winning. Read-only here — restart the process to change it.

3 · Chats

the block that forced this

Two controls, not three. chats.autoHandoff is documented as "hand off automatically" and read by nothing — resolveChatsConfig returns it and the single call site destructures {nudgeAt, handoffAt} only. It is drawn here as the thing it would need to become, greyed and labelled, rather than shipped as a switch with no wire. The live pair gets a preview strip, because "40" and "50" mean nothing without knowing which one speaks.

Chats

this install · overridable per project

When a chat is getting full

Percentages of the answering model's context window, not token counts — the same conversation is half full on one model and a tenth full on another. A chat whose model has no known window is never acted on.

Suggest wrapping upinstall
One message, once. "Worth wrapping up soon; say the word and I'll hand off."

Say it is time to hand offproject
Stronger wording, and offers to write the handoff document. Must be above the first number.
%
Hand off automaticallynot implemented
Would act at the threshold instead of asking. No consumer today — see §2 of the proposal.

What that looks like

0% — quiet40% — nudge55% — hand off100%
Each band speaks once. A fall — the provider compacted — re-arms it, so the next genuine crossing is heard. The defaults sit far below the window's ceiling on purpose: attention dilutes long before context fills.

6 · Advanced

the honest answer

The half that makes "stays in the file" defensible. Every file-only key is listed here with its one-line reason and the file it lives in — so "where is that setting" always has an answer, even when the answer is "a text editor". Both config files render read-only with a copy-path button. Nothing here is editable; that is the point.

Advanced

read-only

File-only settings

Real, consumed, and deliberately without a control. Each reason is its own — they are not interchangeable.

assistants.*.settingSourcesChanges which CLAUDE.md, skills and hooks the agent loads. Failure is invisible — output quality drifts with no error.
assistants.*.binaryPathAbsolute paths to executables. An installation repair, not a preference.
codex.additionalDirectoriesWidens the filesystem sandbox. A web text field is the wrong affordance for granting read access.
container.*Consumed only by the CLI folder-project branch. A control here would do nothing for most runs.
worktree.copyFilesCopies git-ignored files, typically .env. Belongs next to .gitignore, where what is ignored is visible.
worktree.initSubmodulesCorrect as true everywhere; free when there are no submodules. The error that prompts turning it off already names the key.
worktree.pathRequires you to add the directory to .gitignore yourself. A toggle would succeed and leave the repo dirty.
commands.folderAn additional search path with load-bearing ordering. Getting it wrong silently resolves the wrong command.
env (repo file)Superseded by the database env vars above, which win the merge. Two UIs where one silently overrides the other is unanswerable.

Three YAML keys shadow these and do nothing. Two of them ship in the default config.yaml as commented examples, so every install is invited to set them. Removing them is item 1 of §6 — until then this page is the only place that says so.

What is deliberately not here

No per-run panel. --config overrides one invocation, validated fail-fast and sealed encrypted per run. A run's parameters belong on the run launcher, which is a different design question.

No Streaming, Paths or Concurrency sections. Six keys have no consumer (streaming.*, paths.*, concurrency.maxConversations, defaults.copyDefaults, commands.autoLoad, chats.autoHandoff). A control that changes nothing is worse than no control, so they appear only in Advanced, as a warning.

No concurrency row in System. The current SystemPanel shows config.concurrency as though it were the limit in force. It is not, unless it came from the env var. That row either becomes the process value or goes.
